# 企业知识理解与洞察平台 · 一页介绍

**面向**：企业业务负责人 / IT 负责人（懂业务、不必懂技术）  
**用途**：客户沟通、内部立项、路演附件

---

## 一句话定位

**让企业「看懂」自己的文档——自动理解内容、提炼要点、给出跨文档洞察，并支持从洞察一路点到实体与原文。**

---

## 解决什么问题

| 现状 | 痛点 |
|------|------|
| 文档越积越多 | 不知道库里「到底在讲什么」 |
| 只有搜索 | 只能碰关键词，难以判断哪份最相关 |
| 信息分散 | 产品、政策、报告之间缺少统一视角 |

我们用 **理解 + 关联 + 洞察 + 可探索闭环**，把「堆文档」变成「能用起来的知识」。

---

## 核心能力（对外说法）

1. **不只是存文档，而是理解文档**  
   自动提取要点、摘要、主题、关键词，以及文中出现的业务实体（公司、产品等），**不必通读全文也能把握价值**。

2. **不只是搜关键词，而是帮你判断**  
   检索结果展示与文档理解相关的线索（如类型、关键词等），**更快决定打开哪一份**。

3. **不只能问答，还能看「整库在说什么」**  
   **知识库洞察**：跨文档聚合主题、实体与关键词，并给出**结构化结论**与**一句话可带走的总结**——把文档层提升为**决策层信息**。

4. **支持探索，而不是走进死胡同**  
   从洞察、文档、搜索可跳到实体详情；即使某名称尚未进入图谱，也会**可解释地给出相关文档线索**，避免「404 / 系统坏了」的体验。

---

## 典型使用场景

- **业务与合规**：快速掌握政策/制度类文档的重点与适用范围。  
- **产品与售前**：在大量产品资料中定位主题、高频概念与关键实体。  
- **管理与汇报**：用「语料综述 + 关键洞察 + 一句话结论」向上同步「知识库里实际在沉淀什么」。

---

## 和「普通知识库 / 搜索」的差别（记住一句）

> **普通方案帮你「找到文档」；我们帮你「理解文档、看清全貌、记得结论」。**  
> 差异集中体现在 **跨文档洞察（Insight）** 与 **可解释的实体探索**。

---
